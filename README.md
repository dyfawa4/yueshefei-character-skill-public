# 月社妃角色对话 Skill（公开版）

这是一个面向中文角色对话的月社妃 Persona、渐进式 Skill 资料树与可选 AstrBot 运行组件，以《纸上的魔法使》中的人物关系、剧情事实、行为证据和语言习惯为基础。目标不是让模型背诵人物卡，而是让它在即时聊天中既保留妃的味道，又能在涉及原作、人物关系、身体状态和多轮连续性时查到真正需要的证据。

本项目为非官方同人技术项目，与原作开发、发行及版权方无隶属或授权关系。原作人物、设定与相关权利归各自权利人所有。

## V4.0.5 是一次架构更新

旧版主要依靠较长的常驻 Persona 承载高频记忆。V4.0.5 把结构调整为：

```text
常驻 Persona
├─ 月社妃的身份、核心关系和高频语感
├─ 主体、知情与物理连续性合同
└─ Skill 语义导航

Skill
├─ 全人物关系和原作事实
├─ 时间线、路线、原句与事件证据
├─ 语言、动作、情绪和身体反应范围
└─ 成年自愿亲密连续性

可选 AstrBot 组件
├─ V2 当前状态与持续事实
├─ 消息作者、参与者和动作对象分离
└─ 生成前 Skill 内存检索与片段注入
```

Persona 从旧公开版约 71 KB 降到约 27 KB。详细资料没有删除，而是移入 Skill 按需层；普通聊天仍使用从 Skill 证据提炼出的常驻语感，具体事实题再取相关资料。

## 主要特点

- 妃先回应用户当前真正表达的事，再决定毒舌、反话、沉默、直接认真或动作表现，不套固定“傲娇三段式”。
- 区分硬事实、知情边界、行为范围和表达例子；例句不会因为输入相似就自动变成当前场景事实。
- 覆盖四条琉璃、游行寺夜子、伏见理央、汀、日向彼方、暗子、奏、岬、克丽索贝莉露、萤和父母等人物关系。
- 保留幻想图书馆、魔法之书、宝石篇章、关键人生事件、原作台词和行为证据。
- 允许符合人物与当前事实的低风险生活细节和自然联想；不把模型限制成只会确认、拒绝或说不知道。
- 不用人物名、地点、动作、否定、解除或情绪的封闭关键词表决定语义。
- 不使用回复后二次模型审校、重写或多个候选答案拼接。

## V4.0.5 修复摘要

本版本重点处理会严重破坏多轮真实感的问题：

- 进入他人房间、与他人互动或提到人物，不再自动把当前用户切换成该人物。
- 当前消息作者、在场人物、动作执行者和动作接收者分别维护，减少多人场景串位。
- 引用、转述、模仿、假设、疑问和条件句不会被当作真实身份切换或完成事实。
- 世界中已经发生但妃尚未知晓的秘密，与妃可见的表面线索分层维护；看见不舒服不等于知道隐藏原因。
- 手铐、绳索、伤势、药效、临时缓解和解除条件按对象持续，不因换话题或无关否定而整体消失。
- 一个道歉或秘密公开只影响对应事件，不批量推进其他事件。
- 示例中的本岛归来、图书馆镜头、特定伤势和关系阶段不会无依据覆盖普通日常。
- 取消基于自然语言词组裁剪最终台词的做法，避免正常角色内容被误删。
- 修复旧版“允许退出扮演”的冲突说明；月社妃始终以本人身份回应，但不规定固定拒绝台词。

这些边界只限制重大事实跃迁。轻微表情、生活化动作、与当前话题有关的本岛、教堂、图书馆、书、谜题或舞台联想仍可自然出现。

## Skill 是否真的被读取

V4.0.5 的可选 runner 不把“调用了路由模型”当作读取成功。服务启动时，它根据 `skill/resource_catalog.json` 验证全部资源并建立只读内存段落索引；每次需要资料时，记录实际资源 ID、文件哈希、段落行号和注入字符数，再把片段直接放入同一次主生成请求。

正式验证样本中，关系题实际取得 3 类资源、6 个片段、1197 字，内存检索耗时 20.8 ms，随后由主模型一次生成完整角色回复。这里的重点是“资料片段进入主请求”，不是只有路由判定。

公开仓库不上传私人测试语料和线上原始会话；验证方法与日志判定标准写在 `components/README.md`。

## 内容边界

公开版成人内容采用明确、统一的自愿原则：

- 场景必须明确发生在毕业后的成年时间线，所有参与者均为成年人。
- 所有人都必须清醒、能够理解当前行为并可以自由表达选择。
- 同意必须针对当前行为、持续存在，并且可以随时撤回。
- 恋爱或亲属关系、此前同意、挑逗、沉默、束缚状态和身体反应都不能替代当前同意。
- 任何人迟疑、拒绝、改变主意、失去意识或无法自由表达时，当前成人行为立即停止。
- 未明确成年与持续自愿时，沿用毕业前止步接吻的边界，不主动把普通聊天成人化。

满足这些条件时，角色仍保持月社妃本人的自尊、毒舌、敏锐、主动性、复杂依恋和现实身体因果，而不是变成通用成人角色。

## 基础安装

### 1. 安装 Skill

将 `skill/` 整个目录复制到目标应用的 Skill 目录，并把目录名设为：

```text
yueshefei-perspective
```

AstrBot 的典型位置为：

```text
/AstrBot/data/skills/yueshefei-perspective
```

不能只复制 `SKILL.md`。人物、关系、行为、原作和语言证据都位于 `resource/`，`resource_catalog.json` 还负责验证完整性与建立索引。

### 2. 创建 Persona

在对话平台创建 Persona ID `月社妃`，将 `persona/系统提示词.md` 的完整内容设为系统提示词，并绑定 `yueshefei-perspective`。

默认对话对象是四条琉璃。仅提到某个人物、进入其房间或与其互动，不等于切换当前说话者；原创临时人物也可以在对话中自然建立。

### 3. 推荐设置

- 保持全部文件为 UTF-8。
- 优先使用支持长上下文、结构化输出、工具调用和提示缓存的模型。
- 更新前备份 Persona、Skill、runner、配置和会话状态。
- 不同模型对 Skill 的原生加载能力不同；如果平台不安装可选 runner，仍可使用 Persona 与 Skill，但多轮状态和资料预取可靠性取决于平台自身实现。

## 可选 AstrBot 运行组件

`components/runner/` 是在 AstrBot `4.27.2` 上验证的运行补丁，用来提高身份、知情、持续状态和 Skill 片段注入的可靠性。它不是独立插件，也不保证直接兼容其他 AstrBot 版本。

使用前必须：

1. 备份目标 runner 和部署配置；
2. 阅读 `components/README.md`；
3. 核对目标 AstrBot 版本与文件哈希；
4. 先做语法检查和独立测试会话；
5. 确认日志中出现实际 `Skill prefetch` 片段，而不只是路由调用。

不要把该文件直接覆盖到未知版本的框架。

## 性能参考

在作者的正式环境和最终精简样本中：

- 本轮改动直接影响的逐句回复平均约 5.6 秒，最大 6.5 秒。
- 一次实际 Skill 资料题完整回复约 6.3 秒，内存检索约 20.8 ms。
- 主回复、V2 和路由预热后均未持续零缓存。

这些数据只说明该环境中的实现结果，不是对其他模型、网络或部署的性能保证。资料预取速度很快，整体耗时主要仍来自模型请求。

## 升级与恢复

- V4.0.4 已作为独立 GitHub Release 保留，可随时下载旧快照。
- 从 V4.0.4 升级时，应同时更新 Persona、完整 Skill、资源目录、runner 和索引；不要混用不同版本的 `resource_catalog.json`。
- 如果只使用 Persona 与 Skill，不部署 runner，也要完整替换 `skill/` 并重新绑定 Persona。
- 回退时按 `Persona → Skill → runner/索引 → 重启 → 哈希核对 → 独立会话烟雾测试` 的顺序执行。

## 已知限制

- 概率模型仍可能偶尔产生低风险的动作或生活细节偏移；本项目优先防止身份、关系、知情、原作事实和物理连续性等严重错误。
- 不同模型、采样参数、上下文长度和 Skill 支持方式会造成明显差异。
- runner 是对特定 AstrBot 版本的工程补丁，平台升级后需要重新审查兼容性。
- 本仓库不包含状态数据库、服务器凭据、真实用户会话或私人测试语料。
- 原作资料可用于角色对话核对；如需出版或研究级引用，应重新核对合法取得的原始文本。
